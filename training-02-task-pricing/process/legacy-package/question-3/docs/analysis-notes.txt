2017 CUMCM Problem B Question 3
Bundled Task Pricing: Initial Modeling Notes

一、问题三目标

问题三要求在前两问基础上考虑任务打包发布。题面指出，多个任务位置比较集中时，会员可能会争相选择；如果把这些任务联合成任务包发布，需要说明如何修改前面的定价模型，并评价最终任务完成情况的变化。

本问承接问题二。问题二已经给出单任务实用 MILP 定价方案，但仍存在一批任务即使调价到允许边界，预测完成概率仍然较低。因此，问题三不应继续单纯提高单任务价格，而应把相邻任务的竞争关系转化为路线共享关系。

二、从问题二得到的打包候选任务

根据问题二 `results/milp-pricing-results.csv` 的实用 MILP 结果：

全部任务数：835；
实用 MILP 后预测完成概率低于 0.5 的任务数：157；
达到正负 8 元调价边界的任务数：433；
同时满足“预测完成概率低于 0.5 且达到正负 8 元调价边界”的任务数：156。

这些任务是问题三的主要打包候选，因为它们代表“单任务定价已经用足调价空间，但完成概率仍不理想”的任务。

按区域汇总，候选任务分布为：

结合问题一的区域解释，区域 2 大致对应深圳及周边，是三问最核心的打包分析区域。候选逐任务清单保存于：

三、打包机制的经济解释

单任务发布时，位置相近的任务之间主要表现为竞争效应。会员只能逐项挑选任务，会优先选择价格高、距离近、路线顺的任务，低吸引力任务容易被剩下。

打包发布后，包内任务不再互相竞争，而是共同构成一次出行路线。打包可能带来两类收益：

1. 内部竞争减少。原来相邻任务争夺同一批会员，打包后包内任务一起被领取。

2. 出行成本摊薄。会员去一趟可以完成多个任务，平均到每个任务的距离和时间成本下降。

同时，打包也有负面影响：

1. 包太大时总执行时间变长，会员接受意愿下降；

2. 包内路线过长或任务分布不紧凑时，路线成本可能超过共享收益；

3. 若把高概率任务与低概率任务强行绑定，可能反而降低高概率任务的完成效率。

因此，问题三的关键不是“越多任务打包越好”，而是选择空间足够紧凑、单任务完成概率较低且具有路线共享价值的任务包。

四、候选任务包构造

建议采用空间图或 DBSCAN 构造候选包。

方法 A：距离图候选包

对候选任务集合建立无向图。若两个任务之间距离不超过 r 公里，则连接一条边。可取 r = 0.5、1.0、1.5 公里进行敏感性分析。图中的连通分量或局部团可作为候选包来源。

方法 B：DBSCAN 聚类

以任务经纬度为输入，对候选任务进行 DBSCAN 聚类。参数 eps 表示最大邻近距离，min_samples 表示最小打包规模。建议从 eps = 1 km、min_samples = 2 开始。

候选包大小建议限制为：

2 <= m_g <= 5

其中 m_g 为任务包 g 内任务数量。若包过大，可以按最近邻或路线长度把大簇拆成多个小包。

五、包级变量定义

对任务包 g 定义：

m_g：包内任务数；
B_g：任务包总酬金；
A_g = B_g / m_g：包内平均单任务酬金；
D_g：最近会员到任务包入口任务或中心点的距离；
L_g：包内路线长度，可用最近邻路径或最小生成树长度近似；
N_g：任务包周围 2 km 内会员数量；
Q_g：任务包周围 2 km 内会员预订限额之和；
C_g：任务包周围 2 km 内会员信誉值之和；
H_g：包内任务紧凑程度，例如平均两两距离或最大包内距离；
R_g：任务包所属区域。

其中路线长度 L_g 是问题三区别于问题二的核心变量。问题二只有单任务位置，问题三必须刻画“完成整个包需要额外走多远”。

六、修改完成概率模型

问题二单任务模型为：

p_i(P) = Pr(Y_i = 1 | P, X_i)

问题三改为包完成概率：

p_g(B_g) = Pr(任务包 g 被领取并完成 | B_g, Z_g)

其中 Z_g 为包级空间供需和路线特征。

建议写成：

p_g(B_g)
= logistic(
  alpha_0
  + alpha_1 B_g
  + alpha_2 A_g
  - alpha_3 D_g
  - alpha_4 L_g
  + alpha_5 ln(1 + N_g)
  + alpha_6 ln(1 + Q_g)
  + alpha_7 ln(1 + C_g)
  - alpha_8 H_g
  + region effect
)

由于附件没有历史打包数据，不能直接估计所有包级系数。正式建模时可采用“基于问题二单任务概率的结构修正”：

1. 先用问题二 Logistic 模型计算包内任务在新价格下的单任务概率；

2. 将包内竞争任务从外部竞争项中扣除，体现内部竞争减少；

3. 用路线摊薄系数降低等效距离成本；

4. 用包总酬金和包内平均酬金修正任务吸引力；

5. 得到每个候选包的预测完成概率。

七、包完成数与预计成本

若任务包 g 被会员接受，则假设包内任务全部完成。于是：

预计完成任务数：

E_g = m_g p_g

预计支付金额：

C_g = B_g p_g

若需要更谨慎，也可以设置包内完成折扣：

E_g = eta_g m_g p_g

其中 eta_g 与包内路线长度有关，0 < eta_g <= 1。路线越长，eta_g 越小。

八、打包优化模型

问题三需要同时决定哪些任务单独发布、哪些任务打包发布。

定义：

x_i = 1，任务 i 单独发布；
z_g = 1，选择候选任务包 g。

每个任务只能被覆盖一次：

x_i + sum_{g contains i} z_g = 1

目标函数为最大化预计完成任务数：

max sum_i p_i x_i + sum_g m_g p_g z_g

预计支付成本约束：

sum_i P_i p_i x_i + sum_g B_g p_g z_g <= C_max

其中 C_max 可以沿用问题二的 1.15 倍原预计支付成本，也可以与问题二实用 MILP 的预计支付金额保持一致，以便公平比较。

该模型属于带预算约束的集合打包优化问题。若候选包数量较少，可用 MILP 求解；若候选包较多，可先筛选收益最高的候选包，再用贪心或局部搜索求解。

九、与问题二的比较指标

问题三最终需要和问题二实用 MILP 比较：

1. 预测完成数；

2. 预测完成率；

3. 预计支付金额；

4. 被打包任务数；

5. 任务包数量；

6. 平均包大小；

7. 低概率任务数量是否减少；

8. 达到调价上限且仍低概率的任务是否减少；

9. 深圳、广州中心、佛山广州西南部等重点区域的完成率变化；

10. 单个任务价格和任务包总价格是否过于极端。

十、预期结论写法

问题三的预期结论不应写成“打包必然提高所有任务完成率”，而应写成：

在任务密集且单任务调价已接近上限的区域，打包能够减少相邻任务之间的选择竞争，并摊薄会员出行成本，因此对低概率任务具有补救作用。其提升主要集中在深圳及周边等失败热点区域；对东莞等原本高完成率区域，打包必要性较弱。包规模过大或路线过长时，执行负担增加，打包收益会下降。因此，推荐采用小规模、短距离、高失败风险任务的局部打包方案。
