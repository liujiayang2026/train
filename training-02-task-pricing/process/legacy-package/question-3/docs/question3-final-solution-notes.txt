2017 CUMCM B题“拍照赚钱”
问题三最终建模思路：任务打包发布与联合定价优化

一、问题目标

问题三要求考虑任务位置较为集中时，将若干任务联合打包发布，并分析这种发布方式对最终任务完成情况的影响。与问题二的单任务重新定价不同，问题三不仅要决定每个任务的价格，还要决定任务是否单独发布或与相邻任务共同组成任务包发布。

本问的核心目标可以表述为：

在给定预计支付预算约束下，同时优化单任务价格、任务包价格和任务发布方式，使平台的预计完成任务数最大。

也就是说，问题三不是简单地在问题二结果上追加若干任务包，而是把单任务发布和打包发布放入同一个优化模型中统一选择。每个任务最终只能有一种发布方式：要么作为单任务发布并选择一个单任务价格，要么进入某个任务包并共享一个包价格。

二、问题分析

问题一表明，附件一中任务未完成并非随机分布，而是在深圳、广州中心等任务密集区域形成聚集。任务密集区同时存在两种相反作用：一方面，相邻任务会争夺同一批会员，会员倾向于选择价格更高、距离更近或路线更顺的任务，导致部分低吸引力任务被剩余；另一方面，相邻任务若能被同一会员顺路完成，则可以摊薄出行成本，提高整体吸引力。

问题二在单任务发布条件下，通过带单调约束的 Logistic 完成概率模型和实用 MILP 重新配置任务价格，将预测完成率由 62.52% 提高到 68.74%。但仍有部分任务即使达到允许调价边界，预测完成概率仍较低。这说明仅靠单任务价格调整，难以完全解决任务密集区域中的竞争和路线成本问题。

因此，问题三引入打包发布机制：将空间距离较近、单独发布吸引力不足的任务联合成小规模任务包。任务包通过更高的总酬金和更短的平均路线成本吸引会员领取，同时减少包内任务之间的选择竞争。

三、基础数据与候选对象

问题三仍以附件一的 835 个历史任务和附件二的会员信息为基础。每个任务已经在问题二中得到以下信息：

1. 原任务价格；
2. 问题二实用 MILP 新价格；
3. 问题二价格下的预测完成概率；
4. 任务经纬度；
5. 所属空间区域；
6. 周边会员和任务密度等空间供需特征。

为了使打包有明确针对性，首先定义打包核心任务。核心任务满足：

p_i' < 0.5
且
|P_i' - P_i| >= 8

其中，p_i' 为问题二实用 MILP 价格下的预测完成概率，P_i' 为问题二新价格，P_i 为原价格。该条件表示：任务在单任务优化后完成概率仍低，且已经达到最大调价边界，继续单独加价的空间有限。

同时允许核心任务搭配周边顺路任务。顺路任务满足：

1. 与核心任务处于同一空间区域；
2. 与核心任务距离不超过 1 km；
3. 问题二预测完成概率低于 0.75。

这样可以构造“困难任务 + 顺路任务”的混合包，而不是只把低概率任务彼此打包。这样做的原因是：部分中等完成概率任务本身较容易被领取，若与低概率任务空间上顺路，可以增强整个任务包的吸引力，并带动低概率任务完成。

四、空间距离与路线长度计算

将任务经纬度近似转换为公里坐标：

x_i = longitude_i * 111 * cos(mean latitude)
y_i = latitude_i * 111

对候选任务计算两两欧氏距离。设任务包 g 中任务集合为 S_g，包内任务数为 m_g。

为了刻画完成任务包所需的空间移动成本，用包内任务点的最小生成树长度近似路线长度：

L_g = MST length(S_g)

该值越小，表示任务包越紧凑，会员顺路完成包内任务的成本越低。

定义平均边长：

\bar d_g = L_g / max(m_g - 1, 1)

定义任务包紧凑度：

H_g = max(0, 1 - \bar d_g / r)

其中 r = 1 km。若包内任务非常紧凑，H_g 接近 1；若包内任务接近距离阈值边界，H_g 接近 0。

五、候选任务包生成

以低概率边界任务为核心任务，对每个核心任务在同一区域内寻找 1 km 范围内的顺路任务。然后枚举 2 至 5 个任务组成候选包：

2 <= m_g <= 5

为避免任务包过于分散，对候选包设置路线筛选条件：

1. 包内最大两两距离不能过大；
2. 包内平均边长不能过大；
3. 每个包至少包含一个核心任务。

这样生成的候选包均具有明确的空间紧凑性和低概率任务补救意义。

六、任务包价格候选

对于每个候选任务包 g，先计算包内问题二新价格的平均值：

\bar P_g' = average_{i in S_g}(P_i')

设置任务包平均单任务价格候选：

A_gk = rho_k \bar P_g'

其中价格倍率为：

rho_k in {0.85, 0.90, 0.95, 1.00, 1.05, 1.10, 1.15}

于是任务包总酬金为：

B_gk = m_g A_gk

这组价格候选允许平台对任务包设置组合折扣或组合溢价。若 rho_k < 1，表示打包后给予一定折扣，用路线共享节省成本；若 rho_k > 1，表示对困难任务包给予额外补偿，以提高完成概率。

七、单任务完成概率模型

单任务完成概率沿用问题二模型。问题二建立了带 L2 正则和价格单调约束的 Logistic 模型：

p_i(P) = 1 / {1 + exp[-z_i(P)]}

其中：

z_i(P)
= beta_0
+ beta_1 P
+ beta_2 D_i
+ beta_3 ln(1 + N_i)
+ beta_4 ln(1 + G_i)
+ beta_5 ln(1 + Q_i)
+ beta_6 ln(1 + C_i)
+ sum_r gamma_r R_ir

并约束：

beta_1 >= 0

其中，D_i 为任务到最近会员的距离，N_i 为 2 km 内会员数量，G_i 为 2 km 内其他任务数量，Q_i 为周围会员预订限额之和，C_i 为周围会员信誉值之和，R_ir 为空间区域虚拟变量。

对每个任务 i，构造单任务候选价格：

P_ik in {65, 65.5, 66, ..., 85}

并限制：

|P_ik - P_i| <= 8

将每个候选价格代入问题二 Logistic 模型，得到单任务候选完成概率：

p_i(P_ik)

以及单任务预计支付金额：

C_ik = P_ik p_i(P_ik)

八、任务包完成概率估计

由于附件中没有历史打包发布数据，无法直接拟合真实任务包完成概率。因此，本问在问题二单任务完成概率基础上构造包级修正模型。

对任务包 g，在问题二新价格下包内任务的单任务预测概率为 p_i'。先将其转化为 logit 值：

logit(p_i') = ln[p_i' / (1 - p_i')]

取包内平均作为任务包基础吸引力：

base_g = average_{i in S_g} logit(p_i')

然后加入价格修正项、包规模收益、路线紧凑收益和执行负担惩罚。

首先估计包内任务的价格敏感度。对包内任务 i，利用问题二价格变化前后的概率变化近似：

s_i = [logit(p_i') - logit(p_i)] / (P_i' - P_i)

对包内任务取平均并限制在合理范围：

0.02 <= s_g <= 0.20

若任务包平均单任务价格为 A_gk，则价格修正为：

s_g [A_gk - average_{i in S_g}(P_i')]

其次，打包带来包规模收益：

0.42 ln(m_g)

任务包规模越大，总酬金越高，对会员越有吸引力；但规模收益递减，因此采用对数形式。

路线紧凑收益为：

0.55 H_g

任务包越紧凑，会员顺路完成的便利性越高。

执行负担惩罚为：

-0.07(m_g - 1) - 0.10 max(0, L_g - 1)

包内任务越多、路线越长，会员执行负担越大，因此需要扣减完成概率。

若任务包中含有顺路搭配任务，加入小幅顺路锚定收益：

0.12(1 - core_share_g)

其中 core_share_g 表示包内核心低概率任务占比。该项反映较容易完成的顺路任务可以提高任务包整体吸引力，但权重较小，避免过度夸大搭配任务作用。

综上，任务包完成概率估计为：

p_g(B_gk)
= sigmoid{
    average_{i in S_g}[logit(p_i')]
    + s_g [A_gk - average_{i in S_g}(P_i')]
    + 0.42 ln(m_g)
    + 0.55 H_g
    + 0.12(1 - core_share_g)
    - 0.07(m_g - 1)
    - 0.10 max(0, L_g - 1)
  }

其中：

sigmoid(x) = 1 / [1 + exp(-x)]

任务包预计完成任务数为：

E_gk = m_g p_g(B_gk)

任务包预计支付金额为：

C_gk = B_gk p_g(B_gk)

九、联合优化决策变量

问题三最终模型同时决定单任务价格和任务包价格。

对单任务候选价格定义：

x_ik = 1，表示任务 i 单独发布并选择价格 P_ik；
x_ik = 0，表示不选择该候选价格。

对任务包价格候选定义：

z_gk = 1，表示选择任务包 g 并采用包价格 B_gk；
z_gk = 0，表示不选择该包价格方案。

十、联合优化约束

1. 每个任务必须且只能被覆盖一次。

sum_k x_ik + sum_{g contains i} sum_k z_gk = 1

该约束表示任务 i 要么单独发布并选择一个价格，要么进入某个被选中的任务包，不能重复发布，也不能遗漏。

2. 全局预计支付预算约束。

sum_i sum_k P_ik p_i(P_ik) x_ik
+
sum_g sum_k B_gk p_g(B_gk) z_gk
<= C_max

其中 C_max 取问题二实用 MILP 的预计支付金额，或在敏感性分析中放宽 1%、2%。

十一、联合优化目标函数

目标是最大化预计完成任务数：

max
sum_i sum_k p_i(P_ik) x_ik
+
sum_g sum_k m_g p_g(B_gk) z_gk

这是一个带预算约束的混合整数线性规划模型。所有单任务候选概率、单任务预计支付、任务包候选概率和任务包预计支付都在优化前计算完成，因此目标函数和约束均为线性形式。

十二、模型求解

实际计算中，共生成：

单任务价格候选方案：19387 个；
任务包价格候选方案：1407 个；
总候选变量：20794 个。

使用 HiGHS MILP 求解器求解。0%、1%、2% 预算情景均返回最优解，最优性间隙约为 10^{-6}，可认为求解误差很小。

其中顺路搭配任务：11 个；

十四、结果解释

结果说明，在单任务价格和任务包价格联合优化后，即使不增加问题二的预计支付金额，也可以把预测完成率从 68.74% 提高到 70.01%。这表明打包发布并非单纯增加预算，而是通过改变任务组织方式，提高单位预计支付成本带来的完成概率收益。

打包收益主要来自三方面：

1. 低概率边界任务通过与空间相邻任务联合发布，减少了单任务之间的选择竞争；
2. 任务包内部路线共享降低了平均出行成本；
3. 允许剩余单任务重新定价后，预算可以在单任务和任务包之间重新分配，提高整体效率。

与问题二相比，问题三的提升幅度较小但具有补充意义。问题二解决的是单任务价格结构不合理问题，提升约 51.96 个预计完成任务；问题三是在问题二基础上继续改善剩余低概率密集任务，同预算下进一步增加约 10.60 个预计完成任务。

十五、论文写作建议

问题三正文建议按以下结构展开：

1. 问题分析：说明单任务发布下相邻任务存在竞争，打包可利用路线共享；

2. 候选任务筛选：定义低概率边界核心任务和顺路搭配任务；

3. 候选包构造：基于 1 km 空间距离、包规模和路线长度生成任务包；

4. 包完成概率估计：在问题二单任务概率基础上加入包规模、路线紧凑度、执行负担和价格修正；

5. 联合优化模型：同时设置单任务价格变量和任务包价格变量；

6. 结果比较：展示问题二、0%、1%、2% 预算情景下的预计完成数、完成率和预计支付金额；

7. 结论：打包发布是问题二单任务定价的补充，主要改善低概率密集区域。

十六、可直接写入论文的结论段

在问题二单任务定价基础上，本文进一步考虑任务打包发布机制。首先筛选预测完成概率低于 0.5 且达到调价边界的任务作为核心任务，并允许其与 1 km 范围内预测完成概率低于 0.75 的顺路任务组成候选包。随后根据包内路线长度、紧凑度、包规模和包价格构造任务包完成概率，并建立联合 MILP 同时选择单任务价格和任务包价格。模型要求每个任务必须且只能以单任务或任务包形式发布，并在全局预计支付预算约束下最大化预计完成任务数。

计算结果表明，在不增加问题二预计支付金额的情况下，联合打包定价方案选择 46 个任务包、覆盖 120 个任务，使预测完成数由 573.96 个提高到 584.55 个，预测完成率由 68.74% 提高到 70.01%。若允许预计支付金额增加 1% 和 2%，预测完成数分别提高到 587.69 个和 590.76 个。说明打包发布能够缓解任务密集区的内部竞争，并通过路线共享进一步提高任务完成率。

十七、模型局限

1. 附件没有真实打包发布数据，任务包完成概率是基于问题二单任务概率的结构修正估计；

2. 路线长度采用最小生成树近似，没有使用真实道路距离和通行时间；

3. 模型假设任务包一旦被接受，包内任务全部完成，实际中可能存在部分完成；

4. 包规模收益、路线惩罚和顺路锚定收益参数需要通过真实试运行数据进一步校准；

5. 当前模型未显式加入会员时间窗口和在线状态，实际平台部署时应结合会员实时可用性动态更新。

因此，问题三结果应表述为模型预测效果，不能写成实际实施后的真实完成率。
