2017年CUMCM B题“拍照赚钱”的任务定价
问题二推荐定价方案流程与关键指标

一、最终采用的方案

采用“完成率提升型边际效率定价方案”。

方案参数为：

预计支付金额最多增加15%；
单个任务相对原价格最多调整±8元；
任务价格范围为65～85元；
价格以0.5元为调整步长；
每次优先调整单位预计成本能够带来最大完成概率增量的任务。

该方案在成本、完成率和价格稳定性之间取得相对平衡。与预计成本增加20%、单任务调整±10元的完成优先方案相比，本方案成本更低、价格变化更温和；与预计成本只增加5%的方案相比，本方案能够明显改善深圳和广州部分失败热点。


二、方案总体流程

完整流程为：

读取历史任务和会员数据
→ 清洗经纬度、价格和完成状态
→ 构造任务空间供需特征
→ 建立任务完成概率模型
→ 计算每个任务在不同候选价格下的完成概率
→ 设置价格范围、调整幅度和预计成本约束
→ 计算每次加价的边际效率
→ 按边际效率逐步分配价格
→ 输出835个任务的新价格
→ 比较新旧方案完成率和成本
→ 分析不同区域的价格转移和完成率改善。

原平均价格为69.11元。

四、空间特征构造

1. 地理距离

根据任务和会员经纬度计算球面距离。实际代码在研究区域内使用局部平面近似，以提高批量计算效率：

x = 经度 × 111 × cos(区域平均纬度)

y = 纬度 × 111

得到的坐标单位近似为km。

对于最终论文，可以统一写成Haversine距离公式：

d_ij
= 2R arcsin{
sqrt[
sin²((φ_i-φ_j)/2)
+ cosφ_i cosφ_j sin²((λ_i-λ_j)/2)
]
}

其中R=6371 km。


2. 最近会员距离

D_i = min_j d_ij

表示任务i到最近会员的距离。


3. 周围会员数量

N_i = Σ_j I(d_ij≤2 km)

表示任务i周围2 km内的会员数量。


4. 周围任务数量

G_i = Σ_(k≠i) I(d_ik≤2 km)

表示任务i周围2 km内的其他任务数量，用于反映局部任务密度和竞争环境。


5. 会员预订能力

计算任务周围2 km内会员的：

预订任务限额之和；
信誉值之和。

为降低极端值影响，对数量和累计值使用：

ln(1+x)

变换。


6. 区域变量

将任务经纬度标准化后，使用K-means划分为5个空间区域。区域变量用于吸收交通条件、商业环境和会员活跃度等未直接观测的空间差异。

区域中心大致为：

区域0：纬度23.1540，经度113.3065，广州中心及周边；
区域1：纬度22.9543，经度113.7166，东莞及周边；
区域2：纬度22.6627，经度114.0390，深圳及周边；
区域3：纬度22.9890，经度113.1226，佛山及广州西南部；
区域4：纬度23.4680，经度113.3402，广州北部地区。

以上城市名称根据区域中心位置作近似解释，模型实际使用的是空间聚类编号。


五、任务完成概率模型

定义：

Y_i = 1，任务完成；
Y_i = 0，任务未完成。

建立带L2正则化和价格单调约束的Logistic模型：

p_i(P)
= 1 / {1+exp[-z_i(P)]}

其中：

z_i(P)
= β_0
+ β_1P
+ β_2D_i
+ β_3ln(1+N_i)
+ β_4ln(1+G_i)
+ β_5ln(1+Q_i)
+ β_6ln(1+C_i)
+ Σ_r γ_rR_ir

其中：

P为候选价格；
D_i为最近会员距离；
N_i为2 km内会员数；
G_i为2 km内其他任务数；
Q_i为周围会员预订限额之和；
C_i为周围会员信誉值之和；
R_ir为空间区域虚拟变量。

对价格系数增加约束：

β_1 ≥ 0

保证其他条件不变时，提高价格不会降低预测完成概率。


六、模型初步拟合指标

模型在全部历史样本上的初步结果为：

训练样本数：835；
训练集AUC：0.7995；
训练集Brier得分：0.1732；
标准化价格系数：0.2430；
原方案预测完成数：522.00；
原方案预测完成率：62.52%。

模型预测的原方案完成数与实际完成数基本一致，说明模型总体概率均值已经校准。

需要注意：

AUC和Brier得分目前为训练集指标，正式论文中还应补充空间分块交叉验证，不能把训练集结果当成最终泛化性能。


七、候选价格设置

对每个任务i，候选价格满足：

65 ≤ P_i' ≤ 85

价格步长为：

0.5元

同时限制：

|P_i'-P_i| ≤ 8

因此，任务i的最低和最高允许价格为：

P_i,min = max(65, P_i-8)

P_i,max = min(85, P_i+8)

这样能够避免原价65元的任务直接调整到85元，也能防止原价较高的任务被大幅压低。


八、预计支付成本定义

任务未完成时，平台一般不支付任务酬金。因此，主成本指标采用预计支付金额，而不是全部任务标价之和。

任务i在价格P下的预计支付金额为：

c_i(P) = P × p_i(P)

原方案预计支付金额为：

C_old
= Σ_i P_i p_i(P_i)

计算结果为：

C_old = 36,444.28元

推荐方案允许预计支付金额最多增加15%：

C_new
≤ 1.15 C_old

即：

C_new
≤ 41,910.92元

最终方案实际使用的预计支付金额为：

C_new = 41,910.67元

未超过成本上限。


九、边际效率指标

1. 完成概率增量

当任务i的价格从P提高到P+0.5时：

Δp_i(P)
= p_i(P+0.5)-p_i(P)


2. 预计支付金额增量

Δc_i(P)
= (P+0.5)p_i(P+0.5)
- Pp_i(P)


3. 单位预计成本边际效率

E_i(P)
= Δp_i(P) / Δc_i(P)

E_i越大，说明增加同样预计支付成本时，任务i能够获得更大的完成概率提升。


十、价格分配算法

第一步：确定每个任务的最低允许价格

P_i' = max(65, P_i-8)


第二步：计算初始方案

计算所有任务在最低允许价格下的：

预测完成概率；
预计支付金额；
下一次增加0.5元的边际效率。


第三步：建立边际效率优先队列

把所有任务的下一次价格调整按照E_i从大到小排列。


第四步：选择效率最高的任务

取当前E_i最大的任务，将其价格增加0.5元。


第五步：检查成本约束

如果增加后的总预计支付金额不超过：

41,910.92元

则接受本次调价；

否则跳过本次调价。


第六步：更新边际效率

任务价格调整后，重新计算该任务下一次增加0.5元的：

完成概率增量；
预计成本增量；
边际效率。


第七步：重复分配

持续执行：

选择任务
→ 增加0.5元
→ 检查成本
→ 更新效率

直到：

预计支付金额达到15%增幅上限；
或者所有任务达到各自允许的最高价格。


本次求解共接受：

13,162次0.5元价格递增。


十一、算法伪代码

输入：

原任务价格P_i；
任务固定特征X_i；
完成概率模型p_i(P)；
成本上限C_max；
最大调整幅度8元。

初始化：

for 每个任务i:
    P_i' = max(65, P_i-8)
    计算p_i(P_i')
    计算下一次增加0.5元的E_i

while 存在可调整任务:
    选择E_i最大的任务i*
    计算增加0.5元后的预计总成本

    if 预计总成本 ≤ C_max:
        P_i*' = P_i*' + 0.5
        更新任务i*的完成概率和E_i*
    else:
        跳过该次调整

输出：

所有任务的新价格P_i'；
预测完成概率p_i(P_i')；
预计完成数；
预计支付金额。

1. 完成情况

推荐方案预测完成数：574.54；
预计增加完成任务：52.54个。

原方案预测完成率：62.52%；
推荐方案预测完成率：68.81%；
预计完成率提高：6.29个百分点。


2. 价格指标

原平均价格：69.11元；
推荐方案平均价格：73.58元；
平均价格增加：4.47元。

原全部标价总额：57,707.50元；
新全部标价总额：61,437.50元；
全部标价总额增加：3,730.00元；
全部标价总额增幅：6.46%。

预计支付金额增幅为15%，而标价总额只增加6.46%，原因是新方案把价格优先分配给完成概率能够得到明显改善的任务。


3. 价格调整任务数

提价任务：614个；
降价任务：206个；
价格不变任务：15个。

价格调整范围：

最小调整：-8元；
最大调整：+8元；
调整中位数：+8元；
平均调整：+4.47元。

达到65元的任务：156个；
达到85元的任务：13个。

只有13个任务达到85元，未出现统一75%阈值方案中大量任务集中到85元的严重两极化问题。


4. 新价格区间分布

65～69.5元：177个任务；
70～74.5元：367个任务；
75～79.5元：190个任务；
80～85元：101个任务。

新价格主要集中在70～79.5元区间。


5. 成本效率

原方案单位预计完成成本：

36,444.28 / 522.00
= 69.82元/个

推荐方案单位预计完成成本：

41,910.67 / 574.54
= 72.95元/个

每增加一个预计完成任务所需的边际预计成本为：

(41,910.67-36,444.28)
/
(574.54-522.00)
= 104.05元/个

由于提高的是原本较难完成的任务，新增完成任务的边际成本高于原平均完成成本。

十四、与其他方案比较

1. 与成本增加5%、最大调整±5元方案比较

5%成本方案预测完成率：65.32%；
推荐方案预测完成率：68.81%。

推荐方案多提高约3.49个百分点。


2. 与成本增加10%、最大调整±8元方案比较

10%宽幅方案预测完成率：67.36%；
推荐方案预测完成率：68.81%。

增加5个百分点的预计成本预算，完成率进一步提高约1.45个百分点。


3. 与成本增加20%、最大调整±10元方案比较

20%完成优先方案预测完成率：70.50%；
推荐方案预测完成率：68.81%。

完成优先方案只比推荐方案高约1.69个百分点，但预计支付金额还需增加约1,822元，且单任务价格调整更加剧烈。

因此，15%成本增幅、±8元调整幅度位于成本—完成率曲线相对合理的位置。

十六、方案实施建议

1. 按推荐价格先进行小范围试运行，不应直接认定预测完成率为真实实施效果。

2. 优先在深圳、广州中心和佛山部分失败热点试运行。

3. 记录每个会员的实际领取、拒绝、完成和取消数据，以重新估计价格响应。

4. 每完成一批任务后重新训练模型，更新区域难度和会员有效供给。

5. 如果某区域加价后完成率仍然偏低，应考虑任务打包，而不是继续单纯提高单任务价格。

6. 对达到调价上限仍然完成概率较低的任务，应标记为第三问的候选打包任务。

十八、最终结论表述

在任务价格限制为65～85元、单任务价格调整幅度不超过8元的条件下，本文以任务完成概率增量与预计支付成本增量之比作为边际效率指标，按照边际效率从高到低逐步分配价格，并将新方案预计支付金额控制在原方案的115%以内。

模型结果表明，推荐方案将任务平均价格由69.11元提高至73.58元，预计支付金额由36,444.28元增加至41,910.67元，预测完成任务数由522.00个增加至574.54个，预测完成率由62.52%提高至68.81%。新方案重点提高了深圳、广州中心和佛山部分失败热点的任务价格，同时适当降低东莞高完成率区域的任务价格，实现了预计成本在不同空间区域之间的重新配置。

与预计成本增加20%的完成优先方案相比，推荐方案仅损失约1.69个百分点的预测完成率，但节省约1,822元预计支付金额，并避免过多任务达到85元上限。因此，该方案在成本、完成率和价格稳定性之间具有较好的综合表现。
