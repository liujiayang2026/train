2017 CUMCM B题“拍照赚钱”
问题三：任务打包发布模型完整思路

一、问题目标

问题三要求在前两问的基础上，考虑多个任务位置较为集中时，会员可能会在这些任务之间进行选择和竞争。若平台将若干相邻任务联合成任务包发布，需要说明如何修改前面的定价模型，并分析这种发布方式对最终任务完成情况的影响。

本问不是重新从零建立定价模型，而是在问题二“单任务重新定价”的基础上进一步扩展。问题二已经给出了实用 MILP 单任务定价方案，但仍有部分任务在允许调价范围内完成概率偏低，说明继续单纯提高单任务价格并不能充分解决任务密集区的失败问题。问题三的核心就是：通过打包发布，把相邻任务之间的竞争关系转化为路线共享关系，从而提高低概率密集任务的吸引力。

二、与问题一、问题二的衔接

问题一的结论表明，任务未完成并非简单由距离远造成，而是在深圳、广州中心等任务密集区域形成明显聚集。会员在同一区域面对多个邻近任务时，往往优先选择价格更高、距离更近或路线更顺的任务，低吸引力任务容易被剩下。这说明任务密度既有竞争效应，也潜在具有便利效应。

问题二在单任务发布条件下，建立了带单调约束的 Logistic 完成概率模型，并在预计支付成本约束下用实用 MILP 重新配置任务价格。结果显示，实用 MILP 将预测完成率从 62.52% 提高到 68.74%，预计完成任务数从 522.00 个提高到 573.96 个。但是，深圳区域预测完成率仍明显偏低，且存在一批任务已经达到调价边界但完成概率仍不高。

因此，问题三应将这些“单任务调价后仍低概率”的任务作为主要打包对象。这样逻辑上形成了完整链条：问题一发现任务密集区的竞争问题，问题二先尝试单任务价格补偿，问题三再利用打包发布缓解相邻任务竞争和出行成本。

三、打包候选任务筛选

问题三不应对所有任务一律打包。打包主要适合满足以下条件的任务：

1. 位于任务密集区域；
2. 问题二实用 MILP 后预测完成概率仍然较低；
3. 单任务价格已经达到允许调价边界；
4. 与其他低概率任务空间距离较近；
5. 打包后路线长度较短，会员一次出行可以顺路完成。

本次采用的问题三候选任务筛选规则为：

p_i' < 0.5
且
|P_i' - P_i| >= 8

其中，p_i' 为问题二实用 MILP 价格下的预测完成概率，P_i' 为问题二实用 MILP 新价格，P_i 为原价格。

按此规则，从 835 个历史任务中筛出 156 个主要打包候选任务。这些任务的含义是：单任务调价已经基本用足，但预测完成概率仍不足 0.5，继续依靠单任务加价效果有限。

候选任务区域分布为：

区域 0：16 个，平均预测完成概率约 0.4741，平均实用 MILP 价格约 73.28 元；
区域 2：134 个，平均预测完成概率约 0.3732，平均实用 MILP 价格约 74.53 元；
区域 3：6 个，平均预测完成概率约 0.4852，平均实用 MILP 价格约 73.92 元。

其中区域 2 大致对应深圳及周边，是问题三最主要的打包优化区域。

四、打包机制解释

单任务发布时，相邻任务之间主要表现为竞争效应。若多个任务离得很近，会员并不会天然完成所有任务，而是从中选择收益更高、执行更方便的任务。因此，相邻低价或低吸引力任务容易被剩余。

打包发布改变了这一机制。若把相邻任务联合成任务包，会员领取的是一个整体任务包，包内任务不再相互竞争，而是共享一次出行路线。打包带来的收益主要包括：

1. 内部竞争减少。包内任务从多个彼此竞争的任务变成一个整体任务包；

2. 出行成本摊薄。会员到达该区域后，可以顺路完成多个任务，平均到每个任务的距离和时间成本下降；

3. 总报酬提高。任务包总酬金高于单个任务，更容易吸引会员注意；

4. 对低概率任务补救。对于单任务加价后仍低概率的任务，打包可以通过路线共享获得额外吸引力。

但打包也存在负面影响：

1. 包太大时总执行时间变长；
2. 包内路线过长时，会员完成负担增加；
3. 将高概率任务与低概率任务强行绑定，可能降低高概率任务效率；
4. 如果包价格设置过低，虽然成本可控，但完成概率提升有限。

因此，问题三的关键不是简单扩大打包规模，而是选择空间紧凑、低概率、具有路线共享价值的小规模任务包。

五、候选包生成方法

首先读取问题二实用 MILP 的逐任务结果，包括任务编号、经纬度、区域、原价格、问题二新价格和预测完成概率。然后对候选任务进行空间距离计算。

经纬度近似转换为公里坐标：

x = longitude * 111 * cos(mean latitude)
y = latitude * 111

对候选任务计算两两距离，设置初始打包半径：

r = 1 km

若两个任务距离不超过 1 km，则认为它们具有打包可能。候选任务包的规模控制为：

2 <= m_g <= 5

其中 m_g 为任务包 g 包含的任务数。

第一版采用贪心分包：从低概率任务出发，在同一区域内寻找 1 km 内最近任务，形成 2 到 5 个任务的小包。该方法简单直观，但存在局部最优问题，即早期选择可能占用任务，导致后续更优组合无法形成。

优化版采用候选包生成与 MILP 选择：先生成大量可能的重叠候选包，包括 2、3、4、5 个任务组合；再为每个候选包设置多个价格倍率；最后由 MILP 在全局预算下选择最优的包组合。这样可以避免贪心分包的局限。

六、包级变量定义

对任务包 g，定义以下变量：

S_g：任务包 g 中的任务集合；
m_g：包内任务数量；
B_g：任务包总酬金；
A_g = B_g / m_g：任务包平均单任务酬金；
L_g：任务包路线长度；
H_g：任务包紧凑度；
p_g：任务包被领取并完成的预测概率。

路线长度 L_g 采用包内任务点的最小生成树长度近似。该值反映会员完成包内所有任务所需的最低空间移动成本。若包内任务越紧凑，L_g 越小；若任务分布分散，L_g 越大。

定义平均边长：

average_edge_g = L_g / max(m_g - 1, 1)

定义紧凑度：

H_g = max(0, 1 - average_edge_g / r)

其中 r = 1 km。当包内任务距离很近时，H_g 接近 1；当任务分布接近半径上限时，H_g 接近 0。

七、问题二单任务完成概率基础

问题二已经建立了单任务完成概率模型：

p_i(P) = Pr(Y_i = 1 | P, X_i)

采用带 L2 正则和价格单调约束的 Logistic 模型：

p_i(P) = 1 / {1 + exp[-z_i(P)]}

其中：

z_i(P)
= beta_0
+ beta_1 P
+ beta_2 D_i
+ beta_3 ln(1 + N_i)
+ beta_4 ln(1 + G_i)
+ beta_5 ln(1 + Q_i)
+ beta_6 ln(1 + C_i)
+ sum_r gamma_r R_ir

并约束：

beta_1 >= 0

问题三不重新拟合单任务模型，而是沿用问题二中每个任务在实用 MILP 价格下的预测概率 p_i'。这样可以保证问题三与问题二在同一概率口径下比较。

八、任务包完成概率估计

由于附件中没有历史打包发布数据，无法直接用真实打包样本拟合 p_g。因此采用基于问题二单任务概率的结构修正法。

先将包内每个任务的问题二预测概率 p_i' 转换为 logit 值：

logit(p_i') = ln[p_i' / (1 - p_i')]

取包内平均，作为任务包的基础完成倾向：

base_g = average_{i in S_g} logit(p_i')

随后加入打包修正项。打包修正项由三部分组成：

1. 包规模收益：

0.42 ln(m_g)

包内任务越多，任务包总收益越高，但收益不应线性增长，因此用对数形式。

2. 路线紧凑收益：

0.55 H_g

包内任务越紧凑，会员顺路完成的便利性越高。

3. 执行负担惩罚：

-0.07(m_g - 1) - 0.10 max(0, L_g - 1)

包内任务越多、路线越长，执行负担越大，因此对完成概率产生负向影响。

同时考虑包平均酬金变化。利用问题二中任务价格变化与 logit 概率变化估计价格敏感度：

s_i = [logit(p_i') - logit(p_i)] / (P_i' - P_i)

对包内任务取平均，并限制在合理范围：

0.02 <= s_g <= 0.20

若任务包平均单任务酬金为 A_g，问题二包内平均单任务价格为 average(P_i')，则价格修正项为：

s_g [A_g - average(P_i')]

因此，任务包完成概率估计为：

p_g
= sigmoid{
    average_{i in S_g}[logit(p_i')]
    + s_g [A_g - average_{i in S_g}(P_i')]
    + 0.42 ln(m_g)
    + 0.55 H_g
    - 0.07(m_g - 1)
    - 0.10 max(0, L_g - 1)
  }

其中：

sigmoid(x) = 1 / [1 + exp(-x)]

该公式的含义是：任务包的基础吸引力来自包内任务原本的完成概率；打包通过提高总报酬、减少内部竞争和摊薄路线成本增加吸引力；但包太大或路线太长会降低完成概率。

九、任务包预计完成数与预计支付

若任务包被会员接受，则假设包内任务全部完成。因此，任务包的预计完成任务数为：

E_g = m_g p_g

任务包预计支付金额为：

C_g = B_g p_g

其中 B_g 为任务包总酬金。

对未打包任务，仍沿用问题二实用 MILP 的单任务完成概率与预计支付：

E_i = p_i'
C_i = P_i' p_i'

十、第一版贪心打包模拟

第一版采用局部贪心分包方法，在 1 km 范围内形成小规模任务包，并比较两种价格方案：

1. 成本中性打包：每个包的预计支付等于包内任务原来单独发布时的预计支付；

2. 同均价打包：任务包平均单任务价格等于问题二实用 MILP 的包内平均单任务价格。

第一版结果为：

问题二实用 MILP：
预计支付金额 41910.85 元；
预测完成数 573.96 个；
预测完成率 68.74%。

成本中性打包：
形成 44 个任务包；
覆盖 107 个任务；
预计支付金额保持 41910.85 元；
预测完成数提高到 577.35 个；
预测完成率提高到 69.14%；
较问题二增加 3.39 个预计完成任务。

同均价打包：
预计支付金额提高到 42717.21 元；
预测完成数提高到 584.87 个；
预测完成率提高到 70.04%；
较问题二增加 10.92 个预计完成任务。

该结果说明，打包机制确实能改善低概率密集任务，但第一版贪心分包和逐包成本中性约束较保守，提升幅度有限。

十一、优化版集合打包 MILP

为进一步优化打包效果，改用“候选包生成 + 包价格候选 + 集合打包 MILP + 全局预算约束”的方法。

首先生成大量重叠候选包。对每个候选任务，在同一区域内选取 1 km 范围内的若干近邻任务，枚举 2 到 5 个任务的组合。为了避免路线过长，筛除最大两两距离过大或平均边长过大的候选包。

然后对每个候选包设置多个价格倍率：

0.90, 0.95, 1.00, 1.05, 1.10

即：

A_g = multiplier * average(P_i')

这样每个任务包不再只有一个固定价格，而是形成多个“包-价格”候选项。

定义决策变量：

z_gk = 1，表示选择任务包 g 的第 k 个价格方案；
z_gk = 0，表示不选择。

每个任务最多只能进入一个被选中的任务包：

sum_{g contains i} sum_k z_gk <= 1

同一个任务包的多个价格候选最多选一个：

sum_k z_gk <= 1

未被任何任务包覆盖的任务，继续按问题二实用 MILP 单任务方案发布。

目标函数是最大化相对于问题二的预计完成增益：

max sum_{g,k} Delta E_gk z_gk

其中：

Delta E_gk = E_gk - sum_{i in S_g} p_i'

全局预计支付预算约束为：

sum_{g,k} Delta C_gk z_gk <= budget_extra

其中：

Delta C_gk = C_gk - sum_{i in S_g} P_i' p_i'

budget_extra 可以设置为 0%、1%、2% 等不同预算放宽情景。

该模型本质上是带预算约束的集合打包优化问题，可用 MILP 求解。当前实际生成了 670 个候选包价格方案，并用 HiGHS 求解器得到最优解。

十二、优化版结果

优化版结果如下。

问题二实用 MILP：
预计支付金额 41910.85 元；
预测完成数 573.96 个；
预测完成率 68.74%。

优化打包，0% 额外预算：
选择 41 个任务包；
覆盖 99 个任务；
预计支付金额 41910.79 元，基本不增加；
预测完成数 578.37 个；
预测完成率 69.27%；
较问题二增加 4.41 个预计完成任务。

优化打包，1% 额外预算：
选择 39 个任务包；
覆盖 99 个任务；
预计支付金额 42329.92 元；
预测完成数 582.67 个；
预测完成率 69.78%；
较问题二增加 8.71 个预计完成任务。

优化打包，2% 额外预算：
选择 39 个任务包；
覆盖 99 个任务；
预计支付金额 42749.03 元；
预测完成数 586.51 个；
预测完成率 70.24%；
较问题二增加 12.55 个预计完成任务。

与第一版贪心打包相比，优化版在相同预算下将完成增益从 3.39 个提高到 4.41 个；在接近同均价打包的预算增量下，将完成增益从 10.92 个提高到 12.55 个。说明通过全局选择候选包和价格方案，可以更有效地利用打包机制。

十三、与问题二结果的比较解释

问题二实用 MILP 已经在单任务价格范围内充分优化，因此问题三的提升不可能像问题二相对原方案那样大。问题二从原方案到实用 MILP 增加约 51.96 个预计完成任务，属于定价结构的大幅调整；问题三是在问题二基础上的进一步改进，主要针对剩余低概率密集任务。

因此，问题三结果应解释为“边际补充提升”，而不是替代问题二。其主要意义包括：

1. 验证任务密集区并非只能依靠继续加价；
2. 打包能在不增加或小幅增加预计支付的情况下继续提高完成率；
3. 改善主要集中在深圳及周边低概率任务；
4. 打包对高完成率区域意义较小，不宜全局推广；
5. 包规模和路线紧凑度是打包效果的关键。

十四、论文写作建议

论文中建议将问题三写成以下结构：

1. 问题分析：说明单任务定价仍无法完全解决密集低概率任务，引入打包发布；

2. 候选任务筛选：基于问题二实用 MILP 后的低概率边界任务筛选打包对象；

3. 任务包构造：根据空间距离、包大小和路线长度生成候选包；

4. 包完成概率模型：在问题二单任务概率基础上加入包规模、路线紧凑度、路线长度和价格修正；

5. 集合打包优化模型：用 MILP 在全局预算约束下选择包和包价格；

6. 结果比较：报告问题二、贪心打包、优化打包 0%、1%、2% 预算情景；

7. 结论：打包是对问题二单任务定价的补充，主要改善深圳等密集低概率区域。

十五、可以直接写入论文的结论表述

在问题二实用 MILP 定价后，仍有部分任务达到调价边界但预测完成概率低于 0.5，说明单任务加价对这些任务的改善有限。本文进一步将空间相邻的低概率任务构造成候选任务包，并在包级完成概率中引入任务包规模、路线紧凑度和路线长度修正。随后建立集合打包 MILP，在每个任务最多进入一个任务包和全局预计支付预算约束下选择任务包及其价格。

结果表明，在不增加问题二预计支付金额的情况下，优化打包方案选择 41 个任务包、覆盖 99 个任务，使预测完成数由 573.96 个提高到 578.37 个，预测完成率由 68.74% 提高到 69.27%。若允许预计支付金额增加 1% 和 2%，预测完成数分别提高到 582.67 个和 586.51 个。打包收益主要来自深圳及周边低概率密集任务，说明相邻任务联合发布能够缓解单任务之间的竞争，并通过路线共享提高会员接受意愿。

十六、模型局限

1. 附件中没有真实打包发布数据，因此包完成概率属于基于问题二单任务概率的结构修正估计；

2. 路线长度用最小生成树近似，没有使用真实道路网络和通行时间；

3. 模型假设任务包一旦被接受，包内任务全部完成，实际中可能存在部分完成或取消；

4. 会员真实在线状态、时间窗口和任务执行顺序未被观测；

5. 包规模收益、路线惩罚等参数需要在真实平台试运行后重新校准。

因此，论文中应将问题三结果表述为“预测效果”或“模型模拟效果”，不能写成实际实施后的真实完成率。

十八、联合优化修正：同时优化未打包任务价格

前述优化版集合打包 MILP 仍有一个限制：未被选入任务包的任务继续沿用问题二实用 MILP 价格。严格来说，打包机制改变了预算分配方式，未打包任务的价格也应重新优化。否则模型只能回答“在问题二价格固定的前提下，增加打包能改善多少”，还不能称为问题三下的完整最优定价。

因此进一步建立联合优化模型。对每个任务 i，设置单任务价格候选 P_ik，并定义：

x_ik = 1，表示任务 i 单独发布且选择价格 P_ik；
x_ik = 0，表示不选择该单任务价格。

对每个候选任务包 g 及其包价格方案 k，定义：

z_gk = 1，表示选择任务包 g 的第 k 个包价格；
z_gk = 0，表示不选择。

每个任务必须且只能被覆盖一次：

sum_k x_ik + sum_{g contains i} sum_k z_gk = 1

该约束表示任务 i 要么作为单任务发布并选择一个价格，要么进入一个被选中的任务包，不能重复发布，也不能遗漏。

联合优化目标为最大化预计完成任务数：

max
sum_i sum_k p_i(P_ik) x_ik
+
sum_g sum_k m_g p_g(B_gk) z_gk

预计支付预算约束为：

sum_i sum_k P_ik p_i(P_ik) x_ik
+
sum_g sum_k B_gk p_g(B_gk) z_gk
<= C_max

其中 C_max 取问题二实用 MILP 的预计支付金额，或在敏感性分析中放宽 1%、2%。

该模型同时决定四件事：

1. 哪些任务单独发布；
2. 单独发布任务采用什么价格；
3. 哪些任务打包发布；
4. 任务包采用什么总酬金。

因此，它比“问题二价格固定 + 选择任务包”的增量模型更完整。

二十、联合优化后的论文结论写法

在引入打包机制后，若仅固定问题二单任务价格并选择部分任务包，模型只能得到局部改进。为得到更完整的定价方案，本文进一步将单任务候选价格和任务包候选价格同时纳入 MILP。每个任务必须且只能在“单独发布”和“进入任务包”之间选择一种发布方式，并在全局预计支付预算约束下最大化预计完成任务数。

结果表明，在预计支付金额不超过问题二实用 MILP 的条件下，联合优化方案选择 39 个任务包、覆盖 99 个任务，并重新优化其余 736 个单任务价格，使预测完成数由 573.96 个提高到 583.28 个，预测完成率由 68.74% 提高到 69.85%。若允许预计支付金额增加 1% 和 2%，预测完成数可分别提高到 586.32 个和 589.28 个。与固定未打包任务价格的增量模型相比，联合优化在相同预算下进一步增加约 4.91 个预计完成任务，说明打包发布与剩余单任务定价应作为一个整体进行优化。

二十二、增强候选包与价格候选

在联合优化基础上，进一步加入两项改进。

第一，候选包生成不再只允许低概率边界任务之间互相打包，而是采用“困难核心任务 + 周边顺路任务”的方式。核心任务仍定义为：问题二实用 MILP 后预测完成概率低于 0.5 且达到正负 8 元调价边界。周边顺路任务定义为：与核心任务同一区域、距离不超过 1 km，且预测完成概率低于 0.75 的任务。这样可以让低概率任务搭配附近较容易完成的任务，形成更具吸引力的任务包。

第二，包价格候选从原来的 0.90、0.95、1.00、1.05、1.10 五档，扩展为：

0.85, 0.90, 0.95, 1.00, 1.05, 1.10, 1.15

即允许任务包在更宽范围内设置组合折扣或组合溢价。这样可以在预算约束附近找到更细致的价格方案，避免粗价格网格造成的次优。
